# راه‌اندازی ورود و ثبت‌نام مرتکس (Supabase Auth)

صفحه‌های `login.html`، `signup.html` و `account.html` مستقیم با API رسمی Supabase Auth کار می‌کنند.
هیچ کد ایمیلی یا نتیجهٔ ساختگی در آن‌ها نیست؛ **اگر تنظیمات زیر انجام نشود، ثبت‌نام و ورود خطا می‌دهد.**

## ۱) دیتابیس
در Supabase > SQL Editor فایل `migration-auth.sql` را یک بار اجرا کنید.
جدول `profiles`، سیاست‌های RLS و Triggerها ساخته می‌شوند.
پروفایل فقط **بعد از تأیید ایمیل** ساخته می‌شود.

## ۲) تنظیمات Authentication در داشبورد
مسیرها ممکن است در داشبورد کمی جابه‌جا شده باشند؛ نام گزینه‌ها همین‌هاست.

| تنظیم | مقدار |
|---|---|
| Sign In / Providers > Email | فعال |
| **Confirm email** | **روشن (الزامی)** |
| Allow new users to sign up | روشن |
| Secure email change | روشن |
| Minimum password length | ۸ |
| Password requirements | حرف + عدد |
| Email OTP Expiration | ۶۰۰ ثانیه (۱۰ دقیقه) |
| Email OTP Length | ۶ |
| URL Configuration > Site URL | `https://sam8913mt.github.io/marteks/` |
| URL Configuration > Redirect URLs | همان آدرس بالا |

**CAPTCHA را فعال نکنید**، مگر اینکه از من بخواهید فرم‌ها را برایش آماده کنم؛ فرم‌های فعلی توکن کپچا نمی‌فرستند.

## ۳) ارسال ایمیل (SMTP اختصاصی) — الزامی
سرویس ایمیل پیش‌فرض Supabase فقط برای آزمایش است: به آدرس‌هایی غیر از اعضای تیم پروژه ایمیل نمی‌فرستد و سقف ساعتی بسیار پایین دارد.
در **Authentication > Emails > SMTP Settings** گزینهٔ Custom SMTP را روشن کنید و اطلاعات یک سرویس ایمیل (مثل Resend، Brevo، SendGrid، Amazon SES، Mailgun) را وارد کنید.
- از دامنهٔ خودتان یا آدرس فرستندهٔ تأییدشده استفاده کنید و SPF/DKIM را طبق راهنمای همان سرویس تنظیم کنید.
- **Link tracking** را در سرویس ایمیل خاموش کنید.
- بعد از وصل SMTP، سقف ساعتی از Authentication > Rate Limits قابل تنظیم است.
- شرایط و سقف رایگان هر سرویس را خودتان قبل از انتخاب بررسی کنید.

## ۴) قالب‌های ایمیل (کد عددی، نه لینک)
در **Authentication > Emails > Templates** سه قالب زیر را جایگزین کنید.
متغیر `{{ .Token }}` همان کد ۶ رقمی است. از `{{ .ConfirmationURL }}` استفاده نکنید.

### Confirm signup — Subject: `کد تأیید ایمیل مرتکس`
```html
<div dir="rtl" style="font-family:Tahoma,Arial,sans-serif;line-height:2;color:#1b2433">
  <h2>تأیید ایمیل شما در مرتکس</h2>
  <p>برای تکمیل ثبت‌نام، این کد را در صفحهٔ تأیید وارد کنید:</p>
  <p style="font-size:30px;letter-spacing:8px;font-weight:bold;direction:ltr;margin:18px 0">{{ .Token }}</p>
  <p>این کد فقط چند دقیقه معتبر است. اگر شما ثبت‌نام نکرده‌اید، این ایمیل را نادیده بگیرید.</p>
</div>
```

### Magic Link (ورود با کد یک‌بارمصرف) — Subject: `کد ورود به مرتکس`

### Reset Password — Subject: `کد بازیابی رمز عبور مرتکس`

## ۵) جدا بودن کاربر عادی از مدیر
- مدیر فقط کسی است که ایمیلش در `private.app_config` (کلید `admin_email`) ثبت شده؛ همهٔ دسترسی‌های مدیریتی به `public.is_admin()` وابسته‌اند.
- هیچ policy ای برای کاربر عادی دسترسی اضافه نمی‌دهد (بررسی شد). کاربر عادی فقط پروفایل خودش را می‌بیند و فقط نام، نام‌خانوادگی و تلفن را ویرایش می‌کند.
- چون **Confirm email** روشن است، کسی نمی‌تواند با ایمیل مدیر حساب بسازد.
- صفحهٔ `admin.html` و ورود جداگانه‌اش بدون تغییر مانده است.

## ۶) آزمایش دستی بعد از راه‌اندازی (با ایمیل خودتان)
۱. ثبت‌نام با ایمیل واقعی → کد برسد → کد غلط رد شود → کد درست وارد شود → وارد `account.html` شوید و اطلاعات پروفایل را ببینید.
۲. خروج → ورود با رمز عبور.
۳. ورود با کد یک‌بارمصرف ایمیل.
۴. «فراموشی رمز» → کد → رمز جدید → ورود با رمز جدید.
۵. در Table Editor ببینید ردیف `profiles` ساخته شده و ستون رمز عبور ندارد.
۶. ثبت‌نام با ایمیل دوم و شمارهٔ تکراری: ثبت‌نام و تأیید ایمیل کامل می‌شود، ولی پروفایل بدون شماره ساخته و در صفحهٔ حساب از کاربر شمارهٔ دیگری خواسته می‌شود.

## محدودیت‌های شناخته‌شده
- ورود با «نام کاربری» ندارد؛ فقط ایمیل. (Supabase Auth با ایمیل کار می‌کند و جست‌وجوی ایمیل از روی نام کاربری بدون سرور، ایمیل‌ها را لو می‌دهد.)
- شمارهٔ تماس تأیید نمی‌شود (پیامک ندارد)؛ فقط قالب و یکتا بودنش بررسی می‌شود.
- سایت ایستاست؛ «محافظت از صفحهٔ خصوصی» در سمت مرورگر فقط تجربهٔ کاربری است. امنیت واقعی داده‌ها با RLS در دیتابیس انجام می‌شود.
- «مرا به خاطر بسپار» نشست را در localStorage نگه می‌دارد؛ روی رایانهٔ عمومی فعال نکنید.
