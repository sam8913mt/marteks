# راه‌اندازی «مدیریت کاربران» در پنل ادمین مرتکس

تب «🧑‍💻 کاربران» در `admin.html` فهرست کاربران ثبت‌نام‌شده را از یک **Edge Function** امن (`admin-users`) می‌گیرد.
مرورگر هرگز به `auth.users` یا کلید `service_role` دسترسی ندارد؛ هر درخواست در سرور دوباره بررسی می‌شود:
توکن معتبر باشد ← `public.is_admin()` درست باشد (ایمیل مدیر فقط در `private.app_config`) ← ایمیل مدیر تأییدشده باشد.

**این راه‌اندازی را باید خودتان یک بار انجام دهید؛ تا انجام نشود تب کاربران پیام خطا نشان می‌دهد.**

## فایل‌ها
| فایل | تغییر |
|---|---|
| `_private/supabase/migration-admin-users.sql` | جدید: جدول گزارش مدیریتی، policy کاربر غیرفعال، تابع قطع نشست، همگام‌سازی ایمیل، ساخت پروفایل برای کاربران تأییدشدهٔ قدیمی |
| `_private/supabase/functions/admin-users/handler.ts` و `index.ts` | جدید: همهٔ منطق سمت سرور |
| `_private/supabase/config.toml` | جدید: فقط تنظیم استقرار (بدون کلید) |
| `js/admin-users.js` | جدید: رابط تب کاربران |
| `admin.html`, `js/admin.js`, `css/admin.css` | اصلاح کوچک: تب، پنجره، چند خط هوک؛ بقیهٔ تب‌ها دست‌نخورده‌اند |
| `js/auth.js` (+ نسخهٔ کش در `login/signup/account.html`) | پیام فارسی برای «حساب غیرفعال» |
| `_private/tests/*` | آزمایش‌های خودکار (اختیاری؛ لازم نیست منتشر شوند) |

## ۱) دیتابیس
Supabase → SQL Editor → محتوای `migration-admin-users.sql` را یک بار اجرا کنید (اجرای دوباره بی‌خطر است).
پیش‌نیاز: `schema.sql` و `migration-auth.sql` قبلاً اجرا شده باشند.

نکته‌ها:
- **ستون جدیدی در `profiles` اضافه نمی‌شود.** وضعیت حساب از `auth.users.banned_until`، آخرین ورود از `last_sign_in_at` و تأیید ایمیل از `email_confirmed_at` خوانده می‌شود؛ پس با ویرایش `profiles` نمی‌شود ایمیل را «تأییدشده» جلوه داد.
- جدول `admin_audit_log` فقط‌افزودنی است (تریگر جلوی ویرایش/حذف را می‌گیرد) و فقط مدیر می‌تواند بخواند.
- کاربران تأییدشده‌ای که پروفایل نداشتند، پروفایل می‌گیرند؛ داده‌های موجود بازنویسی نمی‌شوند.

## ۲) استقرار Edge Function
با [Supabase CLI](https://supabase.com/docs/guides/cli) (یک بار `supabase login`):
```bash
cd _private
supabase functions deploy admin-users --no-verify-jwt --project-ref xpkckkosnnixshbarieo
```
`--no-verify-jwt` لازم است چون کلید سایت از نوع `sb_publishable_` است؛ اعتبارسنجی توکن و مجوز مدیر داخل خود تابع انجام می‌شود.

### Secrets
- `SUPABASE_URL`، `SUPABASE_ANON_KEY` و `SUPABASE_SERVICE_ROLE_KEY` را خود Supabase به تابع می‌دهد؛ **نه در کد می‌گذارید، نه در GitHub، نه در `js/config.js`.**
- اگر پروژه‌تان کلیدهای قدیمی (legacy) را غیرفعال کرده و `SUPABASE_ANON_KEY` در تابع خالی است:
  `supabase secrets set PUBLISHABLE_KEY=sb_publishable_... --project-ref xpkckkosnnixshbarieo`
- مبدأهای مجاز (CORS): پیش‌فرض فقط `https://sam8913mt.github.io` است. اگر دامنهٔ سایت فرق دارد:
  `supabase secrets set ALLOWED_ORIGINS="https://your-domain.ir" --project-ref xpkckkosnnixshbarieo`
  (برای آزمایش محلی می‌توانید `http://localhost:8123` را هم با ویرگول اضافه کنید؛ بعداً حذفش کنید.)

## ۳) انتشار سایت
فایل‌های سایت را مثل قبل منتشر کنید. آدرس تابع `https://xpkckkosnnixshbarieo.supabase.co/functions/v1/admin-users` است و CSP صفحهٔ ادمین از قبل اجازهٔ اتصال به `*.supabase.co` را دارد.

## ۴) آزمایش دستی بعد از راه‌اندازی
۱. ورود به `admin.html` ← تب «کاربران»: فهرست، آمار، جست‌وجو، فیلتر، مرتب‌سازی، صفحه‌بندی.
۲. جزئیات یک کاربر، ویرایش نام/تلفن (شمارهٔ تکراری باید خطا بدهد).
۳. با یک **حساب آزمایشی** (نه حساب واقعی): غیرفعال کنید ← ورود با رمز و با کد ایمیل باید رد شود ← فعالش کنید ← ورود کار کند.
۴. حذف حساب آزمایشی (باید ایمیل را تایپ کنید) ← در Table Editor ردیف `profiles` آن نباشد.
۵. «📜 تاریخچهٔ مدیریتی» باید همهٔ این کارها را با ایمیل مدیر و زمان نشان دهد.
۶. با یک کاربر عادی وارد سایت شوید، در Console مرورگر توکن خودتان را به تابع بدهید (`POST /functions/v1/admin-users`): باید `403` بگیرید. بدون توکن: `401`.
۷. سورس صفحه و Network را بررسی کنید: هیچ `service_role` یا `sb_secret_` نباید دیده شود.

## کاربرانی که با شمارهٔ موبایل ثبت‌نام کرده‌اند
- حساب‌های اپ **Merteks AI** (نام + شمارهٔ موبایل، بدون ایمیل) در Supabase Auth نیستند؛ تابع آن‌ها را از `admin_ai_accounts()` (در `migration-ai-accounts.sql`) **با توکن خود مدیر** می‌خواند، پس بررسی `is_admin()` در پایگاه داده همچنان انجام می‌شود و کلید تازه‌ای لازم نیست.
- ادغام با شمارهٔ موبایل نرمال‌شده انجام می‌شود: اگر کاربر ایمیلی همان شماره را داشته باشد، یک ردیف می‌ماند (با برچسب «+ حساب اپ»). بقیه با شناسهٔ پایدار `app:<شماره>` نمایش داده می‌شوند.
- کاربر Supabase Auth بدون ایمیل (اگر روزی ورود با شماره فعال شود) هم نمایش داده می‌شود؛ حذف او با تایپ شمارهٔ موبایل تأیید می‌شود.
- به‌جای ایمیل خالی «بدون ایمیل» نشان داده می‌شود؛ فیلتر «بدون ایمیل (ثبت‌نام با موبایل)» و کارت آماری آن اضافه شده است.
- حساب فقط-اپ از این تب ویرایش/غیرفعال/حذف نمی‌شود (مسدودسازی از بخش «🤖 هوش مصنوعی»).
- اگر `admin_ai_accounts` هنوز ساخته نشده باشد، فهرست کاربران ایمیلی مثل قبل کار می‌کند و پنل یک پیام راهنما نشان می‌دهد.

## سیاست‌ها و محدودیت‌ها
- **غیرفعال‌سازی** = ban در Supabase Auth (ورود و تمدید نشست بسته می‌شود) + حذف نشست‌های فعال + policy محدودکنندهٔ `profiles`. ممکن است access token قبلی تا انقضا (پیش‌فرض ۱ ساعت) برای APIهای دیگر معتبر بماند؛ در این پروژه کاربر عادی جز پروفایل خودش به داده‌ای دسترسی ندارد و آن هم بسته می‌شود.
- **حذف** = حذف کامل از Auth؛ `profiles` با `ON DELETE CASCADE` پاک می‌شود و تابع دوباره بررسی می‌کند چیزی یتیم نماند. سفارش‌ها، گفتگوهای دستیار و نظرها به حساب کاربری وصل نیستند (فقط نام/تلفن متنی دارند) و نگه‌داری می‌شوند. فقط یک ردیف در گزارش مدیریتی (ایمیل، زمان، مدیر) می‌ماند.
- مدیر نمی‌تواند حساب خودش را غیرفعال یا حذف کند.
- **ایمیل** از پنل قابل تغییر نیست (تغییر امن با تأیید، توسط خود کاربر). تأیید دستی ایمیل پیاده‌سازی نشده است.
- کاربری که ایمیلش را تأیید نکرده در فهرست «تأییدنشده / بدون پروفایل» می‌آید (نام و تلفن او از اطلاعات ثبت‌نام نمایش داده می‌شود و فقط برای نمایش است) و ویرایش پروفایلش غیرفعال است.
- فهرست تا ۱۰٬۰۰۰ کاربر اول بارگذاری می‌شود (اگر بیشتر شد پنل پیام می‌دهد). جست‌وجو و صفحه‌بندی در سرور انجام می‌شود و نتیجه ۱۵ ثانیه کش می‌شود (دکمهٔ تازه‌سازی کش را دور می‌زند). تب باز هر ۹۰ ثانیه خودکار به‌روز می‌شود.
- محدودیت: ۱۲۰ درخواست در دقیقه برای هر کاربر (در حافظهٔ تابع)، ۶۰ عملیات ویرایش/غیرفعال/حذف و ۱۰ خروجی CSV در هر ۱۰ دقیقه (بر پایهٔ جدول گزارش).
- خروجی CSV شامل ایمیل و تلفن است، ثبت می‌شود و اگر ثبت گزارش ممکن نباشد صادر نمی‌شود. اکسل ممکن است صفر ابتدای شماره را حذف کند؛ ستون را به‌صورت Text وارد کنید.
